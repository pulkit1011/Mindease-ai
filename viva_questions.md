# Viva Questions and Answers: MindEase AI

## A. Problem, SDG 3, Lean Canvas
**1. What problem does your project address?** Many young people feel stress or anxiety but find it hard or uncomfortable to get timely support. The app offers private check-ins, self-care exercises and a limited AI chat, and points users to professional help.

**2. How is it related to SDG 3?** SDG 3 is "Good health and well-being"; Target 3.4 includes mental health. The app supports awareness and self-management, not treatment.

**3. Does your app improve mental health?** I cannot claim that. It has not been tested with real users. The pilot plan in the Lean Canvas is how we would find out.

**4. What is a Lean Canvas?** A one-page business-model plan with nine blocks: problem, customer segments, UVP, solution, channels, revenue, costs, key metrics, unfair advantage.

**5. What are your top three user problems?** Hesitation to seek help, support not reachable at the right time, and generic apps with unclear privacy/safety.

**6. Is your business model validated?** No. It is a set of hypotheses; we need interviews and a consented pilot.

**7. How would you make money ethically?** Institutional licences or grants; never selling data or locking safety information behind payment.

## B. Python, Streamlit, SQLite
**8. Why Streamlit?** It lets me build a web UI in pure Python with no separate frontend, which is easy to explain and demo.

**9. How does Streamlit run pages?** `streamlit run app.py` executes the script from top to bottom on each interaction; files in `pages/` become sidebar pages. Widgets return their current values.

**10. What is `st.session_state`?** A dictionary that survives reruns within a browser session. I use it to keep chat messages in memory only.

**11. Why SQLite?** It needs no server, is in Python's standard library, and supports constraints. It is good for a single-user demo but not for many concurrent users.

**12. What is a primary key and a CHECK constraint?** A primary key uniquely identifies a row (`id`). A CHECK constraint makes the database reject invalid values (e.g. mood outside 1-5).

**13. What is SQL injection and how did you prevent it?** Injection happens when user text is pasted into SQL. I use `?` placeholders so data is never treated as SQL; a test stores `'); DROP TABLE...` as plain text.

**14. How does your migration strategy work?** `PRAGMA user_version` stores the schema version. `init_db` applies any migration with a higher number, so new versions can upgrade existing files.

**15. Why do you validate in Python if SQL has constraints?** Python gives friendly messages for all errors at once; the database constraints are a second safety net.

## C. APIs, environment variables, AI models
**16. What is an API key and why not put it in code?** It is a secret credential. If it is in code and pushed to GitHub, others could use it. I read it from the environment (`.env`, which is git-ignored).

**17. What does `.env.example` do?** It shows the variable names with empty values so others know what to configure, with no real secrets.

**18. How does the chatbot work?** The page calls `get_chat_reply`: safety check first, then (if a key exists) the model with a system prompt and the last 10 messages, otherwise or on error a labelled fallback.

**19. What is a system prompt?** Instructions given to the model that set its role and rules, such as "do not diagnose".

**20. Is a prompt enough to make the chatbot safe?** No. Models can ignore or misinterpret instructions, so I added an independent safety module, limits on what is sent and fixed responses for high-risk cases. Human review would still be needed for real deployment.

**21. What is the fallback and why label it?** If there is no key or the API fails, simple keyword-based replies are used. They are labelled "not generated by an AI model" to avoid misleading users.

**22. What errors from the API do you handle?** Missing key, SDK not installed, rate limit, timeout, connection failure, authentication failure, empty/invalid reply, and unknown errors. A timeout is set so the app does not hang.

**23. What data goes to the AI provider?** Only recent chat text. Mood records and personal notes are never sent.

## D. Safety and privacy
**24. How does your safety module work?** It normalises the message and checks regular-expression patterns by category in priority order: self-harm, immediate danger, abuse, severe distress, medical request.

**25. What happens on a high-risk message?** A fixed, compassionate reply encourages contacting emergency services and a trusted person, lists support contacts, and states that nobody has been alerted. The AI model is not called.

**26. What are the limits of keyword detection?** It can miss indirect or misspelled language and other languages, and can flag harmless text. It is not clinically validated and is not a risk prediction model.

**27. Why do you avoid diagnosing?** Diagnosis needs a qualified professional; a wrong label could harm. The reflection only restates what the user entered.

**28. Why are the phone numbers marked unverified?** I could not verify them online during the build, and wrong numbers could be dangerous. Verified status requires a source URL and verification date in the JSON file.

**29. How is privacy handled?** Data stays in a local SQLite file; chat is not saved; export and delete are available; no user text in logs. But there is no login or encryption, so it is not suitable for public multi-user deployment as is.

**30. What is CSV formula injection?** A spreadsheet may execute text beginning with `=`, `+`, `-` or `@`. I prefix such cells with a quote when exporting.

## E. Analytics, Plotly
**31. How do you compute the stress change?** Mean stress in the last 7 days minus mean in the previous 7 days; shown only if both periods have entries.

**32. Why not label users "healthy" or "unhealthy"?** The scores are self-reports, not clinical measures, and a score change does not prove clinical change.

**33. How do you handle empty data?** Functions return empty DataFrames or `None`, and pages show an empty-state message.

**34. Why use Plotly?** It gives interactive charts that Streamlit displays directly. I add data labels and different markers so meaning does not depend on colour only.

## F. Testing, limitations, future
**35. What did you test?** Database CRUD and constraints, validation boundaries, analytics (including empty data), CSV export, safety true/false positives, AI service errors and secret redaction. 93 cases passed in my environment.

**36. How did you run the tests?** pytest and Streamlit could not be installed in my offline build environment, so a small stand-in runner executed them; I should run `pytest -q` on my own machine to confirm. [Edit this answer after you run pytest.]

**37. What were the main limitations?** Not clinically validated, no real-user testing, simple safety patterns, no authentication/encryption, unverified contacts, English only.

**38. What would you do next?** Safety review with professionals, privacy and authentication, regional languages, ethics-approved pilot.

**39. Why did you use a temporary database in tests?** So tests never change or depend on real user data.

**40. Walk me through `get_chat_reply`.** (1) `assess_message`; if flagged return fixed text. (2) Build `AIService`; prepare last-10 messages. (3) `generate` calls the model inside try/except. (4) If OK return AI text; else return fallback with reason.

## Quick code walkthrough guide
- `config.py`: loads `.env`, defines constants.
- `database.py`: `get_conn` opens/commits/closes; `init_db` runs migrations; CRUD functions use `?`.
- `wellness_service.validate_entry`: converts and checks each field, collects errors, raises `ValidationError`.
- `analytics_service`: pandas `groupby("date").mean()` for daily averages.
- `safety_service`: `_PATTERNS` dict → compiled regex; `assess_message` returns `SafetyResult`.
- `ai_service`: `AIService.generate` → classify errors; `fallback_reply`; `get_chat_reply` orchestrates.
- `pages/*.py`: UI only; each begins with `ui.setup_page(...)`.
