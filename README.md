# MindEase AI: An AI-Powered Mental Wellness Assistant for Youth

A Streamlit web app for mood check-ins, reflection, self-care exercises and a safety-aware chat, built as a
B.Tech project aligned with **UN SDG 3 (Good Health and Well-being)**.

> **Important.** MindEase AI is a general wellness and educational tool. It is **not** a medical device, a
> diagnostic tool, a replacement for a therapist, or an emergency service. It is not monitored by any person.
> If you or someone else may be in danger, contact your local emergency services.

## What it does
- **Wellness check-in:** mood (1-5), stress (1-10), energy (1-10), optional sleep, feelings, notes; a short
  supportive reflection; edit and delete past entries.
- **AI chat:** supportive conversation about everyday stress. Works **without an API key** using clearly labelled offline replies.
- **Mood tracker:** Plotly charts for mood distribution, stress, energy and sleep with a date-range filter.
- **Self-care:** timed breathing, 5-4-3-2-1 grounding, journaling prompts, 1-minute mindfulness, study-break planner, routine checklist.
- **Progress dashboard:** metrics calculated only from your own records, with explanations of their limits.
- **Help and support:** limits, editable support-contact list, CSV export, deletion controls.
- **Safety module:** rule-based detection of high-risk messages that runs *before* any AI call and works offline.

## Limitations (read these)
- Safety detection is a simple pattern check. It is **not** clinically validated and can miss crises or flag harmless text.
- Support phone numbers in `data/support_resources.json` are **marked unverified**; they were written without live checking. Verify them before real use (see below).
- Data lives in a local SQLite file with **no login or encryption**. It is not a secure multi-user service.
- Not tested with real users. No claims are made about health outcomes.
- In the build environment (no internet) the Streamlit UI could not be launched; see "Test status".

## Setup (Windows)
Prerequisite: Python 3.11 or newer from python.org (tick "Add Python to PATH").
```
cd mindease-ai
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
streamlit run app.py
```
macOS/Linux: `source .venv/bin/activate` and `cp .env.example .env`. The browser opens at http://localhost:8501.
The database file `data/mindease.db` is created automatically on first start (no manual step). If a package
fails to install on a very new Python version, use Python 3.11 or 3.12.

## AI configuration and the no-key fallback
1. Get an API key from your AI provider (this project uses Anthropic's API; see https://docs.claude.com).
2. Open `.env` and set `ANTHROPIC_API_KEY=your-key`. Optionally set `ANTHROPIC_MODEL` (check the provider's docs for current model names).
3. Restart the app. The chat page will show "An AI model is configured".

Without a key, or if the API is unavailable (timeout, rate limit, network error), chat uses labelled offline
replies: *"Offline fallback reply (not generated by an AI model)"*. Safety responses never need a key.
**Never commit `.env`** (it is listed in `.gitignore`). Only your recent chat messages are sent to the provider; mood records and notes are never sent.

## Running tests
```
pytest -q
```
Tests use temporary databases and never touch `data/mindease.db`.
Manual UI checklist: (1) open Home, empty snapshot shown; (2) save a check-in, see reflection; (3) edit it in History; (4) open Mood tracker, load demo data, see charts and the demo warning; (5) remove demo data; (6) chat "I'm stressed about exams", see the offline label; (7) chat "I want to end my life", see safety text and no AI label; (8) complete a breathing round and mark done; (9) check Dashboard numbers; (10) download CSV, then delete data with DELETE confirmation.

## Using and updating support resources
Edit `data/support_resources.json`. Set `verification_status` to `"verified"` **only after** you have confirmed the number on the
official source, and fill in `source_url` and `verified_on` (a date). Otherwise the UI shows "Not yet verified".

## Data storage and deletion
Stored locally: check-ins and activity completions in `data/mindease.db`. Not stored: chat messages, API keys.
Help page → Delete data removes rows (check-ins, activity history, or demo data only). Deleting the `.db` file removes everything. Exported CSVs and file backups are not affected.

## Troubleshooting
- `streamlit: command not found`: activate the virtual environment, or run `python -m streamlit run app.py`.
- `ModuleNotFoundError`: run `pip install -r requirements.txt` inside the activated venv.
- Chat says "No AI API key": edit `.env` and restart the app.
- "AI service rejected the credentials": the key is wrong or expired.
- Port busy: `streamlit run app.py --server.port 8502`.
- Charts empty: widen the date range or load demo data.

## Getting a public link (for a form or demo)
`http://localhost:8501` only works on your own computer. Options:
1. **Streamlit Community Cloud (free, recommended):** push the project to a public GitHub repo (without `.env`), sign in at https://share.streamlit.io with GitHub, choose *Create app*, pick the repo, branch `main` and main file `app.py`. Under *Advanced settings* choose Python 3.11 or 3.12 and add secrets: `MINDEASE_PUBLIC_DEMO = "1"` (required) and optionally `ANTHROPIC_API_KEY = "..."`. You get a link like `https://<name>.streamlit.app`. (Menu names can change; see https://docs.streamlit.io.)
2. **Temporary tunnel from your laptop:** tools such as ngrok or Cloudflare Tunnel can expose port 8501, but the link works only while your computer and the app are running.
3. **GitHub repository link:** acceptable when a form asks for source code rather than a live app.

**Public demo mode** (`MINDEASE_PUBLIC_DEMO=1`) gives each visitor a separate temporary database so visitors never see each other's data. Keep it on for any public link. If you add an API key to a public app, anyone can use your quota: set a spending limit with your provider.

## Optional deployment and security notes
Streamlit Community Cloud or a small VM can host the app, but before any public deployment: add authentication; use a
per-user database (or a managed database) with access control and encryption; add a privacy notice and consent;
store the API key in the host's secrets manager; replace unverified support contacts with verified ones; review
safety behaviour with qualified mental health professionals; add rate limiting; and never log user text.
Do not host this publicly as-is for real users.
